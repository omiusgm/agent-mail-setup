# Диагностика

## Сначала отделите сеть от авторизации

Из корня репозитория:

```bash
.venv/bin/python yandex_mail/cli.py probe
.venv/bin/python yandex_mail/cli.py connection_status
```

`probe` устанавливает IMAP/TLS без входа в ящик. Если он падает, смена пароля может быть бесполезна: сначала проверьте DNS, доступность сети, маршрут и статус сервиса. Если TLS проходит, а вход нет, проверьте IMAP, адрес аккаунта и отдельный пароль приложения «Почта».

Инструменты намеренно не печатают пароль и подробный ответ сервера. Код ошибки верхнего уровня не всегда позволяет отличить неправильный пароль от ограничений аккаунта. Ошибка TLS сама по себе не доказывает массовый сбой или атаку.

## TLS обрывается через VPN

В одной проверенной конфигурации возникали `UNEXPECTED_EOF_WHILE_READING` в IMAP и `ERR_CONNECTION_CLOSED` в браузере. При прямом соединении по физическому интерфейсу работали TLS, вход, поиск и чтение.

С согласия владельца сравните оба маршрута без пароля:

```bash
networksetup -listallhardwareports
route -n get default
route -n get imap.yandex.ru
.venv/bin/python yandex_mail/cli.py probe
YANDEX_MAIL_INTERFACE=en0 .venv/bin/python yandex_mail/cli.py probe
```

`en0` замените на проверенный интерфейс. Не меняйте approved VPN endpoints, системные прокси и сетевые политики ради этого примера. Если прямой доступ запрещён владельцем/организацией, такую привязку не используйте. При смене Wi-Fi на Ethernet обновите параметр; на другой ОС этот механизм не работает.

## Поиск пустой, а письмо видно в списке

Серверный поиск Яндекса не находил некоторые свежие тесты по теме. При этом они присутствовали среди последних писем и читались по ID. Причину в проверенной сессии не установили.

```bash
.venv/bin/python yandex_mail/cli.py search_emails --args '{"folder":"INBOX","limit":20}'
```

Сравните заголовки. Используйте возвращённый `message_id` вместе с точным именем папки. Уточните отправителя и даты; не скачивайте весь архив ради одного отрицательного поиска. Для кириллицы и коротких слов результаты могут отличаться от поиска по латинскому названию или адресу отправителя.

## MCP запускается, но почты нет

1. `verify_mcp.py` подтверждает протокол, а не вход в настоящий ящик.
2. Убедитесь, что MCP использует тот же Python и ту же папку, где выполнялась настройка.
3. Проверьте правильность аккаунта и запрос доступа macOS Keychain. Не разрешайте доступ неизвестному приложению.
4. Сравните окружение CLI и MCP: `YANDEX_MAIL_INTERFACE` и `YANDEX_IMAP_HOST` нужно передать серверу явно.
5. Перезапустите сервер/сеанс после изменения конфигурации. В облаке локального файла и Keychain обычно нет.

## Есть массовый сбой

Проверьте свежие сообщения провайдера, время публикации и фактическую доступность нужной операции. Не отключайте TLS-проверку и не пересоздавайте пароли вслепую. Работоспособность веб-страницы не гарантирует чтение архива, поиск или SMTP. Сохраните точную границу проверки: «вход прошёл», «письмо прочитано», «сервер принял отправку», а не просто «всё работает».
